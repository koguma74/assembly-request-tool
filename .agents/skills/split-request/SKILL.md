# 자료요구서 문항 분해

원문 PDF를 읽어 `split.py`를 만들고, 실행 결과가 사용자가 교정한 `data/문항목록.csv`의 형식과 값에 맞게 한다.

## 작업 전 확인

1. `AGENTS.md`, `PROGRESS.md`, `CONTEXT.md`를 먼저 읽는다.
2. `00_문제정의/problem.md`, `design.md`, `처리지침.md` 제2장을 읽는다.
3. `원문/*.pdf`, 기존 `split.py`, 교정된 `data/문항목록.csv`를 실제로 연다.
4. `99_완성본_잠금`은 열거나 풀거나 참고하지 않는다.
5. 원문 PDF와 기존 `data` 파일은 읽기만 한다.

## 의존성 확인

먼저 다음 명령으로 `pypdf` 설치 여부를 확인한다.

```powershell
python -c "import pypdf; print(pypdf.__version__)"
```

설치되지 않았으면 `pip install pypdf`를 사용자에게 보여 주고 허락을 받은 뒤에만 설치한다. PDF 처리는 `pypdf`만 사용하며, Python 표준 라이브러리는 사용할 수 있다.

## split.py 작성

- 작업 폴더 맨 위에 코드 파일은 `split.py` 하나만 만든다.
- 기본 출력은 `data/문항목록.csv`이고 인코딩은 UTF-8-SIG다.
- 교정본을 보존하며 시험할 수 있도록 `--output`으로 별도 출력 경로를 받을 수 있게 한다.
- 출력 열과 순서는 다음과 같다.

`파일명 | 위원회 | 의원 | 제출기한 | 문항번호 | 요구내용 | 세부항목 | 비고`

분해 규칙은 다음과 같다.

1. 첫 줄 `○○위원회 ○○ 의원실 자료요구서`에서 위원회와 의원을 추출한다.
2. `수신: … 제출기한: YYYY. M. D.(요일) HH:MM까지`에서 제출기한을 `YYYY-MM-DD`로 바꾼다.
3. `수신:`, `담당 보좌관:`, `끝.` 줄은 문항에 넣지 않는다. 이름과 연락처는 저장하지 않는다.
4. 줄 맨 앞이 `숫자.`이면 새 문항이다.
5. `가.`, `나.` 줄은 앞 문항의 세부항목으로 둔다. 교정본 형식에 따라 여러 세부항목은 한 셀에서 ` / `로 연결한다.
6. `※` 줄은 앞 문항의 비고로 둔다. 교정본 형식에 따라 비고 값에서는 맨 앞의 `※`와 뒤 공백을 제거한다. 여러 비고는 ` / `로 연결한다.
7. 그 밖의 줄은 바로 앞의 요구내용·세부항목·비고에 공백 하나를 두고 잇는다.
8. 파일명에 적힌 문항 수와 추출 수, 마지막 번호, 번호 연속 여부가 모두 맞을 때만 CSV를 쓴다.

## 교정본과 대조

교정된 `data/문항목록.csv`가 있으면 기본 출력으로 바로 실행하여 덮어쓰지 않는다.

1. `split.py --output <임시 CSV>`로 별도 결과를 만든다.
2. 교정본과 임시 결과의 BOM, 헤더, 행 수, 행 순서, 모든 셀 값을 비교한다.
3. 차이가 있으면 필드별 차이 수와 대표 행을 확인한다. 원문을 다시 확인해 `split.py`를 고친 뒤 재실행한다.
4. 모든 값이 일치한 뒤 임시 CSV를 지운다.
5. 사용자가 실제 문항목록 생성을 요청한 경우에만 기본 출력 경로로 실행한다.

## 확인 및 보고

다음 표를 파일별로 제시한다.

`파일명 | 파일명의 문항 수 | 뽑은 문항 수 | 마지막 번호 | 번호 연속 | 일치(O/X)`

- 일치가 X이면 원인을 찾아 `split.py`를 고치고 다시 실행한다. X인 상태로 완료 보고하지 않는다.
- 세부항목과 비고가 있는 문항 3개를 골라 원문 PDF 추출문과 CSV 결과를 나란히 보여 준다.
- UTF-8-SIG, 열 순서, 전체 행 수를 확인한다.
- `수신:`, `담당 보좌관:`, 연락처, `끝.`이 결과에 없는지 확인한다.
- 작업이 끝나면 바뀐 파일, 검증 결과, 남은 일과 막힌 점을 보고한다.
- `PROGRESS.md`에 완료한 일, 남은 일, 막힌 점과 다음 시작 지점을 기록한다.
