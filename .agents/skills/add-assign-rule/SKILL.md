# 배분 규칙 보강

## 언제 쓰는지

현재 A부 배분 엔진은 원본 규칙에서 시험 40건 중 27건, 접수대장 520건 중 427건을 1순위로 맞힌다. 시험 오답 13건은 범용 키워드 `예산`이 전문 키워드보다 앞선 9건과 `언론`이 앞선 4건이다. 이 오답을 보강하거나 이후 같은 방식으로 배분 규칙을 조정하면서 원본 보존과 회귀 검사가 필요할 때 사용한다.

## 순서

1. `PROGRESS.md`와 `CONTEXT.md`를 먼저 읽고 처리지침 제3장, `web/engine.js`, 조직도, 원본 배분기준표, 시험 문항, 접수대장을 실제로 연다. 엔진이 원본 CSV를 읽는 기준값 27/40·427/520을 다시 확인한다.
2. 오답을 원인별로 묶는다. 현재 기준은 R001 `예산` 우선순위 2가 전문 키워드보다 앞선 9건과 R056 `언론` 우선순위 2가 전문 키워드보다 앞선 4건이다.
3. 원인마다 CSV 수정안을 하나씩 제안하고 사용자 선택을 받는다. 현재 승인안은 R001과 R056의 우선순위를 각각 2에서 1로 낮추는 것이며, 다른 규칙은 승인된 것으로 간주하지 않는다.
4. 원본 `data/배분기준표_소관키워드_304건.csv`는 그대로 두고 `rules_보강.csv` 사본에 승인된 두 행만 반영한다. 원본과 사본의 차이, 304개 규칙, 조직도 26개 과 안의 부서만 사용했는지 확인한다.
5. 보강 사본으로 시험 40건과 접수대장 520건을 다시 분류한다. 전후 1순위 정확도와 새 오답을 비교하고 `PROGRESS.md`에 변경 규칙·결과·남은 연결 작업을 기록한다.

## 끝나는 조건

- 현재 승인안을 적용한 시험 결과가 27/40에서 40/40으로, 접수대장 결과가 427/520에서 490/520으로 바뀌고 두 자료의 새 오답이 모두 0건이다.
- 시험 1순위가 최소 30/40이며, 원본과 사본의 차이가 R001·R056 두 행뿐이고 조직도 밖 과가 0건이다.
- `PROGRESS.md`에 결과를 기록하고, `web/engine.js`의 기본 입력은 여전히 원본 CSV이므로 보강 사본의 실제 연결이 남았음을 분명히 적는다.
- 위 조건을 충족하지 못하면 완료로 보고하지 않고 원인과 다음 선택지를 사용자에게 알린다.

## 하지 말 것

- 원본 배분기준표·조직도·시험 문항·접수대장을 수정하지 않는다.
- 사용자 승인 전에 규칙을 추가·삭제·변경하지 않는다.
- 배분 키워드·제외어·우선순위·부서명을 엔진 코드에 직접 쓰지 않는다.
- 조직도 밖 부서를 만들거나 AI 추천만으로 규칙을 확정하지 않는다.
- 기존에 맞던 문항이 새로 틀렸는데도 전체 정확도만 보고 변경을 채택하지 않는다.
- 별도 요청 없이 `web/engine.js`의 기본 규칙 파일을 보강 사본으로 바꾸지 않는다.
